Intacct Repository Intelligence

Turn a scattered codebase into an evidence-backed system map.

The harness reduces manual discovery and tribal knowledge by connecting business entities, code, APIs, workflows, configuration, security, and impact relationships—while showing where the evidence came from.

Trust before breadth Precision comes first. Unsupported relationships remain unknown instead of becoming confident-looking misinformation.

Why this approach?

Designed for engineers and AI consumers

01

Evidence first

Every fact should trace back to a source file, symbol, configuration artifact, or extracted relationship.

02

Deterministic extraction

Prefer repeatable parsers and explicit mappings over assumptions based only on names or likely locations.

03

Precision before recall

A missing edge is safer than a false edge that leads impact analysis or an AI answer in the wrong direction.

Risks and honest boundaries

Where judgment and validation remain necessary

Accuracy

False relationships

Incorrect edges can produce misleading impact analysis. Explicit mappings, provenance, confidence, and validation are required.

Coverage

Incomplete representation

REST, OpenAPI, XSLT, workflow, and test coverage remain partial. Unknown and unresolved states must stay visible.

Freshness

Graph can lag SQLite

A catalog refresh and graph promotion are separate operations. Consumers must check snapshot and graph freshness.

Semantics

Workflows are currently atomic

The current model represents single actions, not proven multi-step business orchestration.

Operations

Refresh preconditions matter

Repository paths, branches, clean checkouts, dependency closure, and safe refresh bases must be verified.

Boundary

Not a test replacement

The harness supports discovery and analysis; it does not replace runtime, integration, API, or end-to-end testing.

Roadmap

Expand capability only as evidence and validation mature

Now

Increase trust and coverage

  • Expand gold datasets and coverage thresholds
  • Reduce heuristic and unresolved mappings
  • Audit unknown kinds and target classifications
  • Make uncertainty visible in every consumer path
Next

Harden operations

  • Strengthen multi-repository refresh safety
  • Improve SQLite/graph parity validation
  • Track reproducible source snapshots
  • Expand failure-mode regression tests
Later

Model richer behavior

  • Add composite workflows only with sequencing evidence
  • Deepen field, permission, and deployment impact analysis
  • Expand test and API coverage intelligence
  • Improve grounded AI answer evaluation
